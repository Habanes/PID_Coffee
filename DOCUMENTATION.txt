================================================================================
1. WHAT IT DOES
================================================================================
PID-controls the thermoblock of an espresso machine and sequences a full brew.
Six operating modes plus error handling:
  IDLE       - heat to the coffee target temperature and hold (heating PID)
  COFFEE     - run the brew sequence (pre-infuse -> bloom -> preheat -> boost ->
               PID extraction -> done) with a settable total shot time
  STEAM      - drive the block to a steam target temperature (bang-bang)
  HOT_WATER  - both switches active: pump water through the block with the
               heater off, e.g. to cool down after steaming
  ECO        - auto-entered from IDLE after a configurable timeout with no
               activity; heats to a lower energy-saving target instead of
               the coffee target, woken by the rotary encoder or button
  SLEEP      - deeper, second-tier auto-entry from ECO after a second,
               longer configurable timeout (measured off the SAME idle
               clock as ECO's, not reset on the IDLE->ECO hop); heater
               genuinely OFF (no PID hold at all, unlike ECO) - woken the
               same way as ECO, straight back to IDLE
  ERROR      - safe state (heater off, pump off, valve vents) on any fault
Up to 20 named, user-managed presets (create/rename/delete, web-managed
naming), a 4-digit 7-seg display + rotary menu, and a web GUI.


================================================================================
2. HARDWARE I/O
================================================================================
INPUTS
  Signal              Pin      Type            How it is read
  ------------------  -------  --------------  --------------------------------
  Temperature (TSIC)  GPIO 21  digital ZACWire TSIC library getTemperature()
  Pressure            GPIO 1   analog (ADC)    avg 4 samples, reverse divider
  Switches (combined) GPIO 2   analog ladder   1 ADC -> 4 bands via 3 thresholds
  Rotary encoder A/B  GPIO 6/5 digital, ISR    RotaryEncoder lib, pin-change ISR
  Push button         GPIO 4   digital pullup   debounced poll (active LOW)

OUTPUTS
  Signal     Pin              Polarity     Driver
  ---------  ---------------  -----------  -----------------------------------
  Heater SSR GPIO 14          active HIGH  100 Hz hardware-timer ISR (time-prop)
  Pump       GPIO 38          active LOW   digitalWrite from brew SM
  Valve      GPIO 48          active LOW   digitalWrite from brew SM
  Buzzer     GPIO 47          tone()       non-blocking sound engine
  7-seg      digits 3/11/12/8 common anode SevSeg multiplex (UiTask)
             segs 9/13/17/15/7/10/18/16

Pressure transducer: 0.5 V = 0 Bar, 4.5 V = full scale, via divider R1=2.2k
R2=5.1k (ratio 0.6986). Temp sensor TSIC 306 reads up to ~150 C (this caps the
steam range - see section 7).


================================================================================
3. SYSTEM ARCHITECTURE  (cores, tasks, interrupts)
================================================================================
ESP32-S3, dual core. Core 1 = real-time control only; Core 0 = UI + network.

  Task         Core Prio Rate    Does
  -----------  ---- ---- ------  --------------------------------------------
  ControlTask    1    3  100 ms  switch -> temp -> pressure -> brew SM -> PID
                                 -> publish to heater ISR (the whole control)
  UiTask         0    2    2 ms  7-seg refresh + input/menu + buzzer tick
  WebTask        0    1   10 ms  HTTP server (handleClient)

  ISR                Trigger             Does
  -----------------  ------------------  ---------------------------------------
  Heater timer       100 Hz hw timer     time-proportional SSR + hard cutoff
  Encoder            GPIO 6/5 change      counts rotary detents

Boot (CoffeePID.ino setup): initState -> initSettings (load NVS) -> buzzerInit
-> startup jingle -> STARTUP_DELAY_MS -> start the 3 tasks. loop() self-deletes.

4. DATA MODEL
================================================================================
4.1 LIVE STATE  (struct SystemState, guarded by stateMutex; ONE writer each)
  Variable                  Writer        Read by
  ------------------------  ------------  -----------------------------------
  currentTemperature        Temperature   PID, brew SM, heater, display, web
  temperatureSensorError    Temperature   brew SM, web
  currentPressure           Pressure      brew SM, web
  pressureVoltage           Pressure      web (diagnostic)
  switchVoltage             Switches      web (diagnostic)
  switchSteam / switchCoffee Switches     brew SM, web
  currentTargetTemperature  brew SM       PID, display, web
  heaterMode (OFF/FULL/PID) brew SM       PID (gain pick), heater publish, web
  machineState              brew SM       everyone
  coffeeSubstate            brew SM       display, web
  pumpState / valveState    brew SM       (drive GPIO), web
  brewTimerElapsedMs        brew SM       display, web
  coffeePhaseElapsedMs      brew SM       display, web (per-phase countdown/count-up - see 6.3)
  errorReason               brew SM       display, web
  heatingPidOutput          PID           heater publish, web
  displayView               Input         display
  wakeRequested             Input         brew SM (consumed + cleared each cycle, ECO+SLEEP)
  presetSaveMode            Input         display (preset override/save screen active)
  presetSaveTargetRank      Input         display (highlighted target in that screen)

  Access: take stateMutex (STATE_LOCK/UNLOCK) for any read/write, or use
  stateSnapshot() for a consistent copy. The heater ISR does NOT lock - it reads
  volatiles published once per cycle by heaterUpdate().

4.2 SETTINGS  (struct Settings, guarded by settingsMutex, persisted to NVS
    namespace "coffee-pid"; written ONLY via the config layer, IDLE-only)
  GLOBAL (not changed by presets):
    heatingKp/Ki/Kd, brewKp/Ki/Kd      PID gains
    buzzerMute                         silence the buzzer
    encoderInverted                    flip rotary CW/CCW direction (web "Invert Rotary" toggle)
    coffeeTempMax                      over-temp ERROR limit while in COFFEE
    steamTempMax                       over-temp ERROR limit in IDLE/STEAM + ISR
    safePressureMax                    over-pressure ERROR limit (all modes)
                                        (compiled out entirely if HAS_PRESSURE_SENSOR=0
                                        - see Config.h and section 5)
    ecoTargetTemp                      PID target while in ECO
    ecoTimeoutMs                       continuous IDLE time before auto-entering ECO
    sleepTimeoutMs                     continuous IDLE time before auto-entering SLEEP
                                        (from the same clock as ecoTimeoutMs, not reset
                                        on the IDLE->ECO hop; must be >= ecoTimeoutMs,
                                        clamped in sanitizeLocked())
    activePresetIndex                  raw slot index (0..MAX_PRESETS-1) of the active preset -
                                        an internal detail; every user-facing number (7-seg,
                                        web) is a RANK among active slots instead, see below

  PRESETS (Preset[MAX_PRESETS=20]; brew process only) - a fixed pool of slots,
  each either active or not (Preset::active). Only active slots are ever
  shown, numbered by RANK - a 0-based position among the currently-active
  slots, recomputed fresh every time (presetRankCount()/presetSlotForRank()/
  presetRankForSlot() in Settings.cpp) - never by raw slot index. Deleting a
  preset just clears its `active` flag; no data moves, and the remaining
  presets' ranks shift down past the gap for free (e.g. deleting rank 1 out
  of 3 active presets leaves ranks (0,1), not (0,2)). Manual reordering
  isn't supported - order is simply "the order slots were originally
  activated in." Ships with exactly slot 0 active, named "default".
    active                             false = unused slot, hidden everywhere
    name                               PRESET_NAME_MAX_LEN=15 chars, web-set only
                                        (the 7-seg has no text entry - new presets
                                        created there get an auto name like "Preset 3")
    coffeeTargetTemp                   coffee setpoint
    steamTargetTemp                    steam bang-bang target
    preinfuseMaxMs, bloomMs, preheatMs, brewMaxMs   substate durations
    shotMs                             TOTAL brew time - safety backstop, not the normal
                                        way a shot ends (you stop by weight); web-only,
                                        not on the 7-seg menu (see section 8.1)
    preinfuseTargetBar                 pressure that ends pre-infusion early

  LIVE-EDIT MODEL: editing a preset's fields (7-seg menu or web GUI) does
  NOT touch the stored slot above - it edits a separate, single
  `workingPreset` (private to Settings.cpp, exposed via activePreset()),
  which is what BrewStateMachine.cpp actually runs on. Edits take effect
  immediately (live) but are NOT persisted until an explicit save:
  settingsSaveWorkingAsNewPreset() (web-only, activates the first free slot)
  or settingsUpdateSlotFromWorking() (7-seg long-press-and-confirm, or web
  "Update Current" - overwrites a slot's fields, keeps its name, and makes
  that slot the active preset). Switching the active preset
  (settingsSelectPresetBySlot()) loads that slot's stored values into
  workingPreset, discarding any unsaved edits on whatever was active before -
  this also means the encoder/web edits that used to write straight to NVS
  on every tick no longer do (fixed the flash-wear concern from the
  2026-07-16 review's finding #6 as a side effect).

  NVS layout note: this replaced the old fixed-3-preset positional-key
  layout (`p0_ct`/`p1_ct`/`p2_ct`) with the 20-slot `active`/`name`-flagged
  scheme above - a breaking change with no migration path (matches the
  `tempOffset` removal's precedent: orphaned old keys are harmless, just
  unused bytes in flash). First boot after this update resets to a single
  "default" preset; existing tuned presets need to be redone once.

  Storage note: the whole preset array is written/read as ONE NVS blob
  (single "presets" key), not one key per field per slot. A per-key scheme
  (~10 keys x 20 slots = ~200 entries) was tried first and had a real bug:
  adding a NEW preset allocates fresh NVS entries (unlike editing an
  existing one, which overwrites in place), and that many entries was
  enough to exhaust the partition - the failing put() is silent, so a
  newly-added preset would look fine until the next reboot and then simply
  not be there. The blob is one allocation no matter how many presets are
  active, so this can't recur the same way.

  Validation: every write path runs sanitizeLocked() which clamps each field to
  its *_MIN/_MAX range AND enforces coherence:
    coffeeTargetTemp <= coffeeTempMax ;  steamTargetTemp <= steamTempMax
    (the target's only ceiling IS the corresponding safety max - no separate
    fixed *_TARGET_TEMP_MAX constant, no extra headroom margin subtracted)
    shotMs >= brewMaxMs

================================================================================
5. PROCESSES  (each: reads -> writes)
================================================================================
Control loop (Core 1, every 100 ms, IN THIS ORDER so the PID sees a fresh target):

 (1) Switch       reads GPIO 2 + thresholds      -> switchVoltage/Steam/Coffee
                  classify into 4 bands, commit only after SWITCH_DEBOUNCE_MS
                  stable (rejects the steam-mode coffee-opto pulse)
 (2) Temperature  reads TSIC                     -> currentTemperature (=EMA),
                  validate range, EMA filter, fault if bad > interval   temperatureSensorError
 (3) Pressure     reads ADC + calibration         -> currentPressure, pressureVoltage
                  Optional: HAS_PRESSURE_SENSOR=0 (Config.h) compiles this
                  process, the over-pressure trip, and every pressure GUI
                  element out entirely - currentPressure then stays 0 forever,
                  which degrades preinfuse to a pure preinfuseMaxMs timeout
                  automatically (its condition is `pressure >= target ||
                  timeout` - the pressure side just never fires).

SIMULATION_MODE=1 (Config.h, default): bench-test a bare board with nothing
wired (no heater/pump/valve relay, no temp/pressure sensor, no physical
steam/coffee switches) - rotary encoder, button, and display are assumed
real. Replaces processes 1-3's real reads:
  - Temperature: no TSIC read - instead integrates a toy differential model
    each cycle (SIM_HEATER_GAIN/STATIC_LOSS/PUMP_LOSS_C_PER_S, all Config.h,
    eyeballed not measured) off the PREVIOUS cycle's heaterMode/duty/pumpState
    (Temperature runs before the brew SM, so this is always one 100ms-old
    read - irrelevant for a toy model).
  - Pressure: constant SIM_PRESSURE_BAR, no ADC read.
  - Switches: no ADC read at all - switchSteam/switchCoffee are instead
    written directly by Web.cpp's POST /api/sim handler (two toggle buttons
    in a "Simulation" GUI card standing in for the unwired physical
    switches). Still exactly one writer per field, just Web instead of
    Switches for this build.
Heater/pump/valve GPIO writes are untouched either way - driving unwired
pins is harmless, so there is nothing to stub on the output side.
 (4) Brew SM      reads switches, temp, pressure,  -> machineState, coffeeSubstate,
                  fault, limits, active preset        currentTargetTemperature, heaterMode,
                                                      pumpState, valveState (+GPIO),
                                                      brewTimerElapsedMs, errorReason
 (5) PID          reads target, temp, gains,       -> heatingPidOutput
                  heaterMode (computes only in PID mode; resets integral on entry)
 then ControlTask publishes (heaterMode, duty, temp, steamTempMax) to the heater.

Independent:
 (6) Heater ISR   reads heaterMode, duty, temp, cutoff -> SSR GPIO (time-prop;
                  forced off if temp > steamTempMax)
 (7) Input        reads encoder/button (IDLE only)  -> displayView + preset edits
 (8) Display      reads state + active preset       -> 7-seg
 (9) Web          reads everything; writes settings (IDLE only) -> HTTP/API
 (10) Settings/NVS load on boot, persist on change (web/menu)
 (11) Buzzer      reads buzzerMute; sound queue       -> buzzer GPIO (non-blocking)


================================================================================
6. STATE MACHINES
================================================================================
6.1 SWITCH DECODE (process 1)
  Pin voltage  ADC band      -> (switchSteam, switchCoffee)
  ~0 V         <= L1 (534)      BOTH    (1,1)
  ~0.85 V      <= L2 (1526)     STEAM   (1,0)
  ~1.6 V       <= L3 (3040)     COFFEE  (0,1)
  ~3.3 V       >  L3            NEITHER (0,0)
  A band must be stable for SWITCH_DEBOUNCE_MS (600 ms) before it is committed.

6.2 MAIN MACHINE (process 4)
  Transitions (after safety checks, see section 7):
    IDLE  + steam            -> STEAM
    IDLE  + coffee & temp<=BREW_READY_TEMP -> COFFEE (else stay, cooling)
    STEAM + !steam           -> IDLE
    COFFEE+ !steam&!coffee   -> IDLE ;  COFFEE + steam -> STEAM
    (both switches, from ANY state) -> HOT_WATER  (interrupts COFFEE/STEAM
                                                    immediately - not an error)
    HOT_WATER + !steam&!coffee -> IDLE
    HOT_WATER + steam only     -> STEAM
    HOT_WATER + coffee only    -> COFFEE (fresh PREINFUSE, no BREW_READY_TEMP gate)
    IDLE  + !coffee & ecoTimeoutMs elapsed since last IDLE entry -> ECO
    ECO   + rotary/button edge -> IDLE  (any encoder delta or button press)
    ECO   + steam only         -> STEAM ;  ECO + coffee only -> COFFEE (fresh
                                  PREINFUSE, no BREW_READY_TEMP gate - same
                                  trust model as HOT_WATER's exit)
    ECO   + both switches      -> HOT_WATER (via the both-switches rule above)
    ECO   + sleepTimeoutMs elapsed since last IDLE entry -> SLEEP (same idle
                                  clock as the IDLE->ECO hop above, not reset
                                  by it; sleepTimeoutMs >= ecoTimeoutMs always)
    SLEEP + rotary/button edge -> IDLE  (straight to IDLE, not back via ECO)
    SLEEP + steam only         -> STEAM ;  SLEEP + coffee only -> COFFEE
                                  (same trust model as ECO's own exit)
    SLEEP + both switches      -> HOT_WATER (via the both-switches rule above)
    ERROR -> IDLE only when both switches off AND fault cleared (+hysteresis)

  Outputs per state/substate  (heater / pump / valve ; valve true=closed/holds):
    IDLE              PID       off  off
    ECO               PID       off  off   (same outputs as IDLE - only the
                                             PID target differs: ecoTargetTemp)
    SLEEP             OFF       off  off   (heater genuinely off - no PID hold
                                             at all, unlike ECO; deeper/colder
                                             standby, slower to recover)
    STEAM             bang-bang on   closed   (FULL_ON below steamTarget-HYST, else OFF)
    HOT_WATER         OFF       on   closed   (flows through the block, no heat)
    ERROR             OFF       off  open(vent)
    COFFEE PREINFUSE  PID       on   closed
    COFFEE BLOOM      PID       off  closed
    COFFEE PREHEAT    FULL_ON   off  closed
    COFFEE BREW_MAX   FULL_ON   on   closed
    COFFEE BREW_PID   PID       on   closed
    COFFEE DONE       PID       off  open

  ECO/SLEEP timeout clock (idleEntryMs): resets ONLY on a fresh arrival into
  IDLE from a different state (COFFEE done, STEAM/HOT_WATER switch released,
  ERROR cleared, ECO/SLEEP woken) or at boot - NOT on menu-browsing while
  already idle, so cycling 7-seg views does not postpone eco/sleep entry.
  Both ECO's and SLEEP's timeouts measure off this same clock (SLEEP's is
  simply the longer of the two) - entering ECO does not reset it.

6.3 BREW SEQUENCE + SHOT TIMER
  On COFFEE entry brewTimerElapsedMs starts at 0 and counts continuously (the
  standard "total shot time"). Substates advance on their own durations:
    PREINFUSE -> BLOOM  when pressure >= preinfuseTargetBar OR preinfuseMaxMs
    BLOOM     -> PREHEAT  after bloomMs
    PREHEAT   -> BREW_MAX after preheatMs
    BREW_MAX  -> BREW_PID after brewMaxMs (only if before shotMs)
    any       -> DONE     as soon as brewTimerElapsed >= shotMs  (safe truncation)
  DONE holds (pump off) until the coffee switch is released -> IDLE.

  Display (7-seg + web, both read the same server/SM-computed numbers, so
  they always agree - coffeePhaseElapsedMs in SystemState, written by
  BrewStateMachine.cpp each cycle):
    PREINFUSE/BLOOM/PREHEAT/BREW_MAX  count DOWN from that phase's own
                                       duration (e.g. "Pr07" -> "Pr00"),
                                       static (no blink) - unlike the idle
                                       settings views, this is a read-only
                                       countdown, not an editable value
    BREW_PID (and DONE, frozen)       count UP continuously from the moment
                                       BREW_MAX started - NOT reset at the
                                       BREW_MAX->BREW_PID handoff, and NOT
                                       the same as brewTimerElapsedMs (which
                                       includes PREINFUSE/BLOOM/PREHEAT too).
                                       Shown plain (no 2-letter label) since
                                       it's no longer a fixed-duration phase.
                                       DONE freezes it at whatever it read
                                       the instant DONE was entered, rather
                                       than continuing to climb while the
                                       machine waits for the switch release.
  shotMs itself is a safety backstop, not the everyday way a shot ends (you
  stop by weight) - default 120s, web-GUI-only (see section 8.1).


================================================================================
7. SAFETY MODEL
================================================================================
Temperature is the EMA-filtered raw TSIC reading: currentTemperature =
EMA(raw), used as-is by the PID, the limits, and the display.

Mode-aware over-temp ERROR limit:
  COFFEE                                -> coffeeTempMax (~120)
  IDLE / STEAM / HOT_WATER / ECO / SLEEP -> steamTempMax  (~145)   (the lenient
                                           limit - HOT_WATER is expected to run
                                           right after steaming when the block
                                           may still be hot; IDLE/ECO/SLEEP use
                                           it so the post-steam cooldown does
                                           not trip; ECO/SLEEP's own targets
                                           are well below it regardless (SLEEP
                                           has no target at all, heater is off)
                                           - this is just the shared selector,
                                           no per-mode-specific code needed)
  ISR hard cutoff = steamTempMax (independent backstop if the loop misbehaves)
Over-pressure ERROR: currentPressure > safePressureMax (all modes). Disabled
entirely on no-sensor builds (HAS_PRESSURE_SENSOR=0, see section 5) - can
never trip and never blocks an ERROR clear.
Brew-readiness gate: COFFEE can only START when currentTemperature <= BREW_READY_TEMP.

Spike debounce: over-temp must persist OVERTEMP_TRIP_MS (300 ms) and over-pressure
OVERPRESSURE_TRIP_MS (100 ms) before tripping ERROR, so noise/overshoot is ignored.
Temp sensor fault (no valid reading > TEMP_ERROR_INTERVAL_MS) trips immediately.
(Both-switches is no longer an error trip at all - see section 6.2, it enters
HOT_WATER instead.)

ERROR clears to IDLE only when BOTH switches are released AND the fault is gone
(temp < limit - ERROR_CLEAR_HYSTERESIS, pressure ok, sensor ok).

NOTE: TSIC 306 saturates ~150 C, so all steam limits are kept below 150; the
bang-bang cutoff, the over-temp trip and the ISR cutoff all stay readable.

PID anti-windup: integral accumulates only in HEATER_PID mode and is reset on
entry to PID mode (covers steam->idle and brew_max->brew_pid). Steam never uses
the PID (bang-bang FULL_ON/OFF), so its output is simply ignored there.


================================================================================
8. USER INTERFACE
================================================================================
8.1 7-SEG + ROTARY (IDLE only; locked while COFFEE/STEAM/HOT_WATER/ECO/SLEEP/ERROR)
  Encoder direction is invertible via the settings.encoderInverted flag (web
  "Invert Rotary" toggle in the System card) - applied as a sign-flip on the
  raw encoder delta in Input.cpp's syncInput(), before any view logic sees it,
  so it also covers the ECO/SLEEP wake-on-movement check. Default is the
  existing physical direction (unset = today's behavior).
  Button cycles 8 views; encoder acts within the editable ones. Every
  editable view blinks its value digits (label stays static) as the "this
  is live, the rotary changes it" cue - one shared blink timer (Display.cpp's
  blinkOn()) so SET_COFFEE, the 4 phase-timing views, and PRESET all blink in
  sync rather than drifting apart. Each of the 4 per-phase timing views shows
  a 2-letter label + 2-digit seconds (e.g. "Pr12"); the display saturates at
  99s if a duration is ever set above that (real range per Config.h is wider,
  but every practical value is well under it):
    TEMP        show currentTemperature      (encoder idle, no blink)      "C093"
    SET_COFFEE  edit active coffeeTargetTemp  (+/- COFFEE_TEMP_STEP_WHOLE,
                            whole degrees only - no decimal display or edit
                            anywhere on the 7-seg, including STEAM's >=100C
                            readout, which needed the integer path anyway;
                            value blinks)                                  "S093"
    PREINFUSE   edit active preinfuseMaxMs   (+/- PREINFUSE_STEP_MS, blinks) "Pr03"
    BLOOM       edit active bloomMs          (+/- BLOOM_STEP_MS, blinks)    "bL05"
    PREHEAT     edit active preheatMs        (+/- PREHEAT_STEP_MS, blinks)  "Ph02"
    BOOST       edit active brewMaxMs        (+/- BOOST_STEP_MS, blinks)    "bS08"
    PRESET      switch active preset, by rank among active presets, not raw
                            slot (see section 4.2) - "P_01".."P_20" (2nd
                            digit blank, number blinks); long-press opens
                            the override/save screen, below
    IP          scroll the web IP             (encoder idle, no blink)

  PRESET override/save screen (long-press from the PRESET view, a nested
  mode rather than a DisplayView of its own - see Input.cpp): blinking
  "OrXX" (rotary scrolls XX across every active preset's rank, "Or00" style,
  plus one virtual "new" slot shown as "Or+" - a hand-built "+" glyph drawn
  across the last 2 digits, since there's no natural letter for "new" that
  doesn't collide with something else in this set). Short-press commits: on
  an existing rank, overwrites that preset's fields from the current working
  edits and makes it the active preset (settingsUpdateSlotFromWorking()); on
  "new", activates the first free slot with an auto name like "Preset 3"
  (settingsSaveWorkingAsNewPreset() - renaming is web-only, the 7-seg has no
  text entry). Long-press again while in this screen cancels back to the
  PRESET view with no save. Takes priority over the "too hot to brew"
  override (section 8.1 above) since the user is mid-gesture.
  The old single TIMER view (total shotMs) was removed from this on-device
  menu - shotMs is still a real safety cap (see section 6.3), just web-GUI-
  only now ("Brew Timing" card); you stop a shot by weight, not a timer, so
  it no longer needed on-device editing.
  While not IDLE the display auto-shows: COFFEE -> per-phase countdown/
  count-up (labeled like the idle timing views - "Pr07" counting down, etc. -
  see section 6.3 for the exact sequence and where it switches to counting
  up), STEAM -> temperature (dash-prefixed), HOT_WATER -> temperature (H-prefixed,
  same glyph reused for the "too hot to brew" indicator), ECO -> static "ECO",
  SLEEP -> static "SLEP" (neither blinks - both are expected background
  states), ERROR -> scrolling short word identifying the fault (HIGH/PRESS/
  SEnSOr - no blink phase).
  In ECO or SLEEP, any encoder movement or button edge requests a wake
  straight back to IDLE (SLEEP does not hop through ECO first) - no view
  cycling, no settings edits happen in either state.
  In IDLE, if the coffee switch is active but currentTemperature exceeds
  BREW_READY_TEMP (the brew-readiness gate silently refusing to start),
  the selected menu view is overridden with a blinking "HOt " - same
  override precedent as STEAM/HOT_WATER/ERROR/ECO/SLEEP. Reverts to the normal
  menu view the instant the switch releases or the block cools enough to
  actually start brewing. The web GUI mirrors this: the status badge shows
  "Too Hot" (existing amber "heating" style, no new CSS - a normal wait
  state, not an error) and the status line reads "Too hot to brew -
  waiting for block to cool below {BREW_READY_TEMP} degC" (BREW_READY_TEMP
  exposed via /api/state as brewReadyTemp).

8.2 BUZZER (non-blocking, mute-able)
    encoder step      short tick
    button press      short click
    enter COFFEE/STEAM/HOT_WATER ascending perfect fifth (A4 -> E5)
    exit to IDLE      descending (E5 -> A4)
    active-to-active handoff (e.g. COFFEE interrupted into HOT_WATER)  silent
    auto-enter ECO/SLEEP  silent (unattended transition, could fire overnight)
    wake ECO/SLEEP -> IDLE  short click (input-acknowledgment, not the mode jingle)
    ERROR             repeating beep-boop siren (while in ERROR)
    boot              startup jingle

8.3 WEB GUI (style from NewWebsiteIdea/, dark espresso theme)
  Served from PROGMEM: /, /style.css, /script.js, /chart.js (vendored locally
  so the temperature chart still renders with no internet path, e.g. AP mode).
  API:  GET /api/state     live values (1 s poll); includes coffeePhaseRemainingSec/
                             coffeePhaseElapsedSec while brewing, computed server-side
                             from the same coffeePhaseElapsedMs the 7-seg reads, so
                             the dashboard's brew-status line always matches it exactly
        GET /api/settings  globals + the WORKING preset copy (live, possibly unsaved
                             edits - see 4.2's LIVE-EDIT MODEL) + wifiSsid, non-secret
        POST /api/settings  apply globals (persist immediately) + preset-scoped fields
                             (stage into the working copy only, IDLE only, else 409)
        GET /api/presets   active presets only, by rank + name (section 4.2)
        POST /api/preset          select active preset {rank} (IDLE only)
        POST /api/preset/save     save working copy as a new preset {name} (IDLE
                                   only; 409 if the 20-slot pool is full)
        POST /api/preset/update   overwrite the active preset's fields from the
                                   working copy, keep its name (IDLE only)
        POST /api/preset/delete   deactivate a preset {rank} (IDLE only; 409 if
                                   it's the last remaining one)
        POST /api/preset/rename   rename a preset {rank, name} - web-only, the
                                   7-seg has no text entry (IDLE only)
        POST /api/reset     restore defaults - single "default" preset in slot 0
                             (IDLE only)
        POST /api/wifi      save new station SSID/password (NOT IDLE-gated -
                             persists to NVS only, no live reconnect/reboot;
                             takes effect on the next natural restart)
        POST /api/sim       SIMULATION_MODE only - set fake switchCoffee/
                             switchSteam (NOT IDLE-gated; see section 5)
  The page is read-only (banner + disabled controls, class "cfg") whenever the
  machine is not IDLE; the server also rejects writes outside IDLE. The WiFi
  and Simulation cards are deliberately NOT in the "cfg" lock group - editable
  regardless of machine state, since neither touches anything live. No
  steam-PID row; no switch override in a real (non-simulation) build.

  WiFi: station mode using NVS-stored credentials ("wifi" namespace, keys
  "ssid"/"pass") if the user has ever saved one via the WiFi card, else the
  compile-time WIFI_SSID/WIFI_PASSWORD fallback (Config.h) - connects for up
  to WIFI_CONNECT_ATTEMPTS * WIFI_CONNECT_DELAY_MS (~60s) before falling back
  to a self-hosted AP, "PID_COFFEE" / "ESPRESSO26" (AP_SSID/AP_PASSWORD). The
  full GUI is served identically in both modes, so a machine with no home
  WiFi at all can be run entirely over its own AP, indefinitely.

9. CONCURRENCY
================================================================================
  stateMutex     guards SystemState   (STATE_LOCK / STATE_UNLOCK)
  settingsMutex  guards Settings + NVS (SETTINGS_LOCK / SETTINGS_UNLOCK)
  soundQueue     FreeRTOS queue, ControlTask/Input -> Buzzer (cross-core safe)
  Rules that keep it safe:
   - Both mutexes created in setup() before any task starts.
   - No code ever holds both mutexes at once (no nesting) -> no deadlock.
   - Neither mutex is recursive (plain xSemaphoreCreateMutex()) - the preset
     rank helpers (presetRankCount() etc., Settings.cpp) self-lock and must
     never be called from a function that already holds settingsMutex; the
     internal preset lifecycle functions iterate settings.preset[] directly
     instead of calling back into them, for exactly this reason.
   - Readers prefer snapshots (stateSnapshot/settingsSnapshot/activePreset).
   - ISRs take NO locks: heater reads volatiles published each cycle; encoder
     only counts.
   - All task loops are non-blocking (vTaskDelayUntil / vTaskDelay); the only
     delay() is the boot jingle, before tasks start. tone() and the brew sounds
     are non-blocking.
   - Settings writes hold settingsMutex during the NVS write (tens of ms) but
     only happen in IDLE, so at worst one control cycle is delayed.

11. BUILD - ARDUINO IDE SETUP  (hardware: ESP32-S3 N16R8 = 16MB flash, 8MB OPI PSRAM)
================================================================================

11.1 ESP32 BOARD SUPPORT (one-time)
  File -> Preferences -> Additional Boards Manager URLs, add:
    https://espressif.github.io/arduino-esp32/package_esp32_index.json
  Tools -> Board -> Boards Manager -> install "esp32" by Espressif Systems,
  version 3.x  (REQUIRED - the code uses the core-3.x timer API
  timerBegin(freq)/timerAlarm; it will NOT build on core 2.x).
  Tools -> Board -> esp32 -> "ESP32S3 Dev Module".

11.2 TOOLS MENU SETTINGS (for the N16R8 module)
  Board ................................ ESP32S3 Dev Module
  Port ................................. (your COM port, e.g. COM5)
  USB CDC On Boot ...................... Enabled  if Serial is on the NATIVE USB
                                         port; Disabled if on the UART bridge
  CPU Frequency ........................ 240MHz (WiFi)
  Core Debug Level ..................... None     (Info/Error only when debugging)
  USB DFU On Boot ...................... Disabled
  Erase All Flash Before Upload ........ Disabled (set Enabled ONCE for a clean
                                         first flash to wipe old NVS, then revert)
  Events Run On ........................ Core 0   <-- IMPORTANT: keeps Core 1 free
                                         for the real-time ControlTask
  Flash Mode ........................... QIO 80MHz
  Flash Size ........................... 16MB (128Mb)        (N16)
  JTAG Adapter ......................... Disabled
  Arduino Runs On ...................... Core 1   (loop task self-deletes; fine)
  USB Firmware MSC On Boot ............. Disabled
  Partition Scheme ..................... 16M Flash (3MB APP/9.9MB FATFS)
                                         (any scheme with an NVS partition works)
  PSRAM ................................ OPI PSRAM           (R8 = octal PSRAM)
  Upload Mode .......................... UART0 / Hardware CDC
  Upload Speed ......................... 921600  (drop to 460800 if uploads fail)
  USB Mode ............................. Hardware CDC and JTAG
  Zigbee Mode .......................... Disabled

11.3 LIBRARIES
  From Library Manager (Tools -> Manage Libraries -> search & Install):
    SevSeg          (Dean Reading)      - 7-segment display
    RotaryEncoder   (Matthias Hertel)   - rotary encoder
    TSIC                                - TSIC temperature sensor
                    (if not in Library Manager, install the ZIP from
                     https://github.com/Schm1tz1/arduino-tsic )

  MANUAL install - the rancilio/CleverCoffee PID fork (NOT the stock PID lib):
    The code needs SetIntegratorLimits() and SetSmoothingFactor(), which the
    standard "PID by Brett Beauregard" does NOT have. Use the fork:
      Repo:  https://github.com/rancilio-pid/Arduino-PID-Library
      ZIP:   https://github.com/rancilio-pid/Arduino-PID-Library/archive/refs/heads/master.zip
    Install: Sketch -> Include Library -> Add .ZIP Library... -> select the ZIP.
    CONFLICT: do NOT also have the stock "PID" library installed - both define
    PID_v1.h and the IDE may pick the wrong one ("no member named
    SetIntegratorLimits"). Remove the stock PID if present.

  Bundled with the ESP32 core (no install): WiFi, WebServer, Preferences, FreeRTOS.

  Harmless build message: "Multiple libraries were found for WiFi.h ... Not used:
  WiFiNINA". The IDE correctly uses the ESP32 core WiFi. To silence it, delete the
  WiFiNINA folder from your Arduino/libraries.

11.4 FLASH
  Open the sketch (CoffeePID.ino - all .cpp/.h in the same folder compile together).
  Optionally set real WIFI_SSID / WIFI_PASSWORD in Config.h section 10 before
  flashing - this is only the first-boot fallback now; credentials can also be
  set later from the WiFi card in the web GUI (see section 8.3), including
  entirely over the machine's own "PID_COFFEE" AP if it has no home WiFi.

11.5 BENCH-TUNING AFTER FIRST FLASH
  - coffeeTempMax (120): raise if the PREHEAT/BREW_MAX bursts trip it.
  - SWITCH_LEVEL_1/2/3 ADC thresholds: verify against the real divider.
  - COFFEE_TEMP_STEP / encoder detents: confirm one comfortable step.
