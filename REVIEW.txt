NEWVERSION REVIEW SWEEP
=======================
Full static review of the rebuilt firmware. No toolchain was available locally,
so this is a logic/architecture audit, not a compile. Library deps + a build
pass are listed at the end.

FILE SET (one concern per module):
  Config.h  State.*  Settings.*                         (foundations)
  Switches.* Temperature.* Pressure.*                   (sensing - control loop)
  BrewStateMachine.* Pid.* Heater.*                      (control + actuation)
  Display.* Input.* Buzzer.*                             (UI)
  Web.*                                                  (remote UI)
  ControlTask.* UiTask.*  CoffeePID.ino                  (wiring)


1. DATA FLOW / SINGLE-WRITER  (verified: every live var has one writer)
-----------------------------------------------------------------------
  currentTemperature      <- Temperature ; read by Pid, BrewSM, Display, Web, ControlTask
  temperatureSensorError  <- Temperature ; read by BrewSM, Web
  currentPressure         <- Pressure    ; read by BrewSM, Web
  pressureVoltage         <- Pressure    ; read by Web
  switchVoltage/Steam/Coffee <- Switches ; read by BrewSM, Web
  currentTargetTemperature<- BrewSM      ; read by Pid, Display, Web
  heaterMode              <- BrewSM      ; read by Pid (gain pick), ControlTask->Heater
  machineState/substate   <- BrewSM      ; read by everyone
  pumpState/valveState    <- BrewSM (+GPIO) ; read by Web
  brewTimerElapsedMs      <- BrewSM      ; read by Display, Web
  errorReason             <- BrewSM      ; read by Web
  heatingPidOutput        <- Pid         ; read by ControlTask->Heater, Web
  displayView             <- Input       ; read by Display
  Settings/presets        <- config layer only (Web POST + Input menu), IDLE-only
  RESULT: no field has two writers. Switch override removed -> Switches is the
  sole writer of the switch flags.


2. MUTEX / SEMAPHORE DISCIPLINE  (verified: no nesting -> no deadlock)
---------------------------------------------------------------------
  Two mutexes: stateMutex, settingsMutex. Created in setup() BEFORE any task
  (initState, initSettings) so no task can touch them before they exist.
  Every site takes ONE lock, does minimal work, releases, then (if needed)
  takes the other. Checked all callers: Temperature, Pressure, Switches, Pid,
  BrewSM, Display, Input, Buzzer, ControlTask, Web - none hold both at once.
  Snapshots (stateSnapshot / settingsSnapshot / activePreset) copy-under-lock
  so readers never hold a lock while working.
  Buzzer events cross cores via a FreeRTOS queue (soundQueue) - correct
  primitive for ControlTask(core1)->UiTask(core0) signalling.
  NOTE: settings edits hold settingsMutex during the NVS write (tens of ms);
  this can delay ONE control cycle if a save lands mid-cycle. Only happens in
  IDLE (writes are IDLE-gated), so harmless.


3. ISR SAFETY  (verified)
-------------------------
  Heater ISR (onHeaterTimer, IRAM_ATTR): reads only volatiles (g_mode, g_dutyMs,
  g_cutoff, g_counter) + digitalWrite. No locks, no allocation. Volatiles are
  published once per cycle by heaterUpdate() from ControlTask. (digitalWrite in
  the timer ISR is the same pattern as the old known-working firmware.)
  Encoder ISR (encoderISR, IRAM_ATTR): only encoder.tick(). No locks.


4. FREERTOS COMPLIANCE  (verified)
----------------------------------
  3 tasks: Control (core1, prio3, 100ms), Ui (core0, prio2, 2ms),
  Web (core0, prio1, 10ms). Control + Ui use vTaskDelayUntil (jitter-free).
  Web uses vTaskDelay. Heater = 100Hz hardware timer (timerBegin/timerAlarm,
  ESP32 core-3.x API, autoreload) - non-blocking. NO blocking delay() anywhere
  in the task loops; the only delay() is buzzerStartupJingle()/STARTUP_DELAY_MS
  in setup() BEFORE tasks start. tone()/noTone() are non-blocking. Buzzer
  multi-note jingles are sequenced by millis() ticks, never delay() (this fixes
  the old delay(170) brew sounds that would have stalled the control loop).
  loop() vTaskDelete(NULL) frees the Arduino loop task.


5. STATE TRANSITIONS x SWITCH COMBINATIONS  (verified - no broken combo)
-----------------------------------------------------------------------
  Safety trips are checked FIRST every cycle (except while already ERROR):
    temp sensor fault / both switches / over-temp(mode limit) / over-pressure
    -> ERROR.
  Switch truth table (after debounce), per state:
    state   steam coffee -> action
    IDLE     0     0      stay IDLE (PID heat to coffeeTarget)
    IDLE     1     0      -> STEAM
    IDLE     0     1      -> COFFEE if temp<=BREW_READY_TEMP, else stay (cooling)
    IDLE     1     1      -> ERROR (both switches)
    STEAM    1     0      stay STEAM (bang-bang)
    STEAM    0     x      -> IDLE (IDLE re-evaluates a held coffee switch)
    STEAM    1     1      -> ERROR
    COFFEE   1     1      -> ERROR
    COFFEE   0     0      -> IDLE
    COFFEE   1     0      -> STEAM
    COFFEE   0     1      run substate sequence
    ERROR    x     x      stay until BOTH off AND fault cleared (+hysteresis)
  Coffee substates: PREINFUSE->BLOOM->PREHEAT->BREW_MAX->BREW_PID->DONE.
    Shot timer (continuous from COFFEE entry) forces DONE the instant
    brewElapsed>=shotMs from ANY substate -> a too-short shot truncates safely,
    never underflows. BREW_MAX->BREW_PID only fires if it happens before shotMs.
  Debounce (600ms) rejects the steam-mode coffee-opto pulse, so STEAM never
  flickers into COFFEE/BOTH.
  No combination leaves outputs undefined: driveOutputs() covers every
  (state,substate); ERROR forces heater off / pump off / valve open(vent).


6. CONTROL CORRECTNESS  (verified)
----------------------------------
  Loop order: switch -> temp -> pressure -> BrewSM(decide) -> Pid(compute) ->
  heaterUpdate. So the PID always controls to the FRESH target + correct gain
  set (no stale-by-one-cycle bug).
  Offset is subtracted once at the sensor; PID + all limits operate on the true
  temperature - no offset coherence traps.
  PID anti-windup: computes/accumulates only in HEATER_PID mode; integral reset
  on entry to PID mode (covers steam->idle and brew_max->brew_pid). Brew gains
  only during SUB_BREW_PID; heating gains otherwise.
  Mode-aware over-temp: coffeeTempMax in COFFEE, steamTempMax in IDLE/STEAM (so
  the post-steam cooldown does not false-trip). ISR backstop = steamTempMax.


7. WEB GUI vs STYLE GUIDE  (verified)
-------------------------------------
  Embedded CSS uses the exact palette + class vocabulary from
  NewWebsiteIdea/style.css: accent #b6926e, panels #020404, page gradient,
  green .btn-primary / red .btn-reset+.btn-emergency, .card/.card-title,
  .value-display, .control-grid-3, .status-display (+brewing/steam/error),
  .diag-*, pulse animation, responsive collapse. (Condensed, not byte-identical,
  but visually faithful.) Per WebUI Style.txt field mapping: steam PID row and
  switch override are NOT present; presets, tempOffset, coffee/steam max, and a
  "Shot time total" field ARE. UI goes read-only (banner + .locked) when
  machineState != IDLE, and the server also 409s any write outside IDLE.

8. KNOWN RISKS / TUNE-ON-HARDWARE
---------------------------------
  - coffeeTempMax = 110: the intentional FULL_ON PREHEAT/BREW_MAX bursts could
    briefly spike the block past 110 and trip ERROR mid-shot. If so, raise it.
  - SWITCH_LEVEL_1/2/3 (ADC) and COFFEE_TEMP_STEP/encoder detents are starting
    values; verify on the bench.
  - digitalWrite inside the timer ISR: carried over from the known-working old
    firmware; if any flash-related instability appears, switch to direct GPIO
    register writes.


9. BUILD (must be done on a machine with the toolchain)
-------------------------------------------------------
  No arduino-cli/PlatformIO present here, so this was NOT compiled.
  Required libraries (same as the old build):
    - TSIC            (temperature sensor)
    - PID_v1          (rancilio fork - needs SetIntegratorLimits/SetSmoothingFactor)
    - SevSeg          (7-segment)
    - RotaryEncoder   (encoder)
  Core libs: WiFi, WebServer, Preferences (bundled with ESP32 core 3.x).
  Open NewVersion/CoffeePID.ino, select the ESP32-S3 board, install the four
  libraries, set real WiFi credentials in Config.h (section 10), then build.
